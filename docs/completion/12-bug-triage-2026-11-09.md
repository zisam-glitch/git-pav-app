## Plan

One concern per PR, as `AGENTS.md` asks. Each fix comes with a test that fails before it.

1. **Session stays alive (B1).** App only. Sign out only on a 401 from refresh; keep the session on network
   errors and 5xx and show the offline banner. Test: mock refresh returning 503 and a network error.
2. **Confirmation screen (B4, B5).** App only. Poll the single appointment, stop once confirmed, drop the
   `appointments[0]` fallback (send the user to Bookings if there's no id).
3. **UK time on clinician and records screens (B6, B14).** App only. Use `uk-time.ts` everywhere; extend the
   existing time-zone test to scan these screens.
4. **Hold and Redis outages (B3, B8).** Backend + app. 503 when Redis is unreachable; return seconds remaining
   and count down from receipt.
5. **Reschedule overlap (B9).** Backend. Write the test; fix only if it fails.
6. **Request timeouts (B7).** App. One timeout in `authFetch`, with a clear "took too long" error.
7. **Backend tidy-up batch (B10, B11, B12, B13).** Backend. Param validation, limits, one Stripe client, no
   invented clinician name.
8. **Errors to Sentry (B15).** App.
9. **Consent at booking (B2).** After the DPO answers.
10. **Second pass** over what this one didn't read: `van.ts`, `admin.ts`, `auth.ts`, the payments webhook,
    `website/` and `admin-dashboard/`.
